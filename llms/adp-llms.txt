# Automatic Data Processing (ADP)

> ADP is a global human capital management provider serving more than one million businesses. Its developer platform exposes REST APIs across payroll, worker demographics, time and labour, benefits, talent and recruiting for ADP Workforce Now, Vantage HCM, RUN, Enterprise HCM, iHCM and GlobalView. Access is gated: an application must be registered with ADP, authenticate with OAuth 2.0 over mutual TLS with an ADP-issued X.509 certificate, and be consented to by each client organization.

## How ADP APIs actually work

- **Reads are REST, writes are events.** There is no `PATCH /hr/v2/workers/{aoid}`. A change is a POST of a named event to `/events/{domain}/v1/{eventName}` (e.g. `worker.personal-communication.email.add`, `worker.leave.cancel`, `worker.rehire`).
- **Call `/meta` before every write.** `GET <event>/meta` returns the per-tenant, per-actor validation rules — required fields, max lengths, regex patterns, enumerated code lists. ADP states the OpenAPI alone is not sufficient to build a valid write.
- **Queries speak OData.** `$select`, `$filter`, `$top`, `$skip`, `$orderby`, `$count`, `$expand`, `$search` on GETs. Paging past the end returns `400`, not an empty `200`.
- **There is no idempotency key.** Do not blind-retry a write; re-read and confirm first.
- **Every call carries context headers**: `orgoid`, `associateoid`, `roleCode`, plus act-as / on-behalf-of delegation.
- **Mutual TLS is mandatory** on both `accounts.adp.com` and `api.adp.com` (UAT: `uat-accounts.adp.com`, `uat-api.adp.com`).
